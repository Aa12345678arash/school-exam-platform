# امنیت و حریم خصوصی دانش‌آموزان

این سند حداقل الزامات امنیتی پروژه را پیش از ورود داده واقعی تعیین می‌کند.

## داده‌های ممنوع در Git
- نام کامل و فهرست واقعی دانش‌آموزان
- کد دانش‌آموزی، شماره تماس، نشانی یا اطلاعات خانوادگی
- رمز عبور، token، کلید API، secret و فایل محیطی واقعی
- پاسخ‌برگ یا تصویر دست‌نویس قابل انتساب به دانش‌آموز
- خروجی‌های واقعی کارنامه و نمرات

برای توسعه از داده‌های ساختگی و غیرقابل انتساب استفاده شود.

## احراز هویت و مجوز
- رمز عبور خام ذخیره یا log نمی‌شود.
- شناسه ورود به‌تنهایی مجوز دسترسی نیست.
- نقش و عضویت مدرسه/کلاس در سمت سرور کنترل می‌شود.
- دانش‌آموز فقط آزمون‌ها و پاسخ‌های مجاز خودش را می‌بیند.
- والد فقط پرونده فرزند/فرزندان متصل و تأییدشده را می‌بیند.
- آموزگار فقط کلاس‌ها و آزمون‌های مجاز را مدیریت می‌کند.
- دسترسی مدیر مدرسه به داده‌های همان مدرسه محدود می‌شود.
- عملیات حساس در audit log ثبت می‌شوند.

## آزمون و پاسخ‌ها
- کلید پاسخ در API عمومی یا payload دانش‌آموز قرار نمی‌گیرد.
- آزمون منتشرشده به نسخه تغییرناپذیر متصل است.
- هر تغییر کلید یا rubric ثبت و قابل ممیزی است.
- فایل‌های پاسخ دست‌نویس private هستند و URL عمومی دائمی ندارند.
- زمان و وضعیت ذخیره پاسخ به کاربر نشان داده می‌شود.

## داده و زیرساخت
- انتقال داده با HTTPS.
- استفاده از secrets محیط استقرار؛ فایل secrets وارد Git نمی‌شود.
- دسترسی پایگاه داده با اصل حداقل مجوز.
- در صورت استفاده از Supabase، Row Level Security برای همه جداول حساس فعال و با آزمون منفی بررسی می‌شود.
- پشتیبان‌گیری و بازیابی پیش از انتشار واقعی تمرین می‌شود.
- خطاها نباید اطلاعات شخصی یا secret را افشا کنند.

## دروازه پیش از پایلوت واقعی
- بازبینی مجوزها برای هر نقش.
- تست دسترسی متقاطع بین دو دانش‌آموز و دو کلاس.
- تست عدم افشای کلید پاسخ.
- تست فایل‌های بارگذاری‌شده و محدودیت دسترسی.
- سیاست رضایت/اطلاع‌رسانی والدین و مدرسه بررسی شود.
- فرایند رسیدگی به رخداد و بازیابی مشخص باشد.

تا تکمیل این موارد هیچ اطلاعات واقعی دانش‌آموزی در سامانه آزمایشی وارد نشود.
